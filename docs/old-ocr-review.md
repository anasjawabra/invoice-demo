# Review of the earlier OCR / document-linking demo code (what it really did)

**Conclusion: nothing in the earlier code performed OCR or read a PDF. Every "extraction" was simulated or canned. There is no working OCR or PDF-text capability in the history to reuse.** Inspected: the local repository in full (66 commits, all branches including `remotes/origin/*`, the tags `v1.0-static`, `v2.0-react`, `v2.1-static-dashboard`, `demo-baseline-final`, `phase0-fixes`), searched for OCR / PDF libraries and calls (`tesseract`, `createWorker`, `getDocument`, `pdfjs`, `readAsText`, `readAsArrayBuffer`, `recognize(`). **No access is missing:** no other repository, service or file store was referenced by the old code.

**What was reused:** the three sample invoice PDFs, now as fixtures — a test reads `invoice_normal_alrajhi.pdf` through the real text-layer reader and finds `INV-2026-0731` (the Arabic presentation-form labels are normalised before matching). The regex idea of `extractReferences` survives only as the new, tested `extractFromText` (with classification of invoice vs other numbers). Everything else (file-name scan, canned fields, amount scoring) was removed because it presented simulation as extraction.

**What it means for delivery:** the capabilities that exist now were built from scratch in `51134ca`/`d566e7d`: real **text-layer reading** (pdf.js) and **supplied-text import**. **OCR performed by this system remains pending**; the macOS Vision experiment (`docs/ocr-assessment/`) is **exploratory evidence on one synthetic page, not an integrated capability and not an accuracy assessment**.
