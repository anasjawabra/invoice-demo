### Request / response
`POST /api/plan-actions` body = the usual data request (`scope`, `cfg`, `decisions`, `links`, `linkInfo`, `fileExclusions`) plus optional `entityGaps: { [Amanah key]: planned − collected (SAR, positive = behind) }` and `groupBy: 'entity' | 'municipality'` (a municipal `scope.muni` implies municipality level). The population is the **stock** (every invoice issued up to the cut-off, like `snapshot().stock`), honouring access mask, organisation narrowing, scope filters (incl. `scope.status`) and the review overlay.

```
{ version, kind:'planning_action_lines', cutoff, asOf, yearEnd, agedDays:180, level:'entity'|'municipality', scope,
  classes:[{key,ar,en,actionable,count,remaining,dueByYearEnd,lines}],               // A B C D E U
  lines:[ { id:'<entity>|[<muni>|]<source>|<class>', rank, entity:{key,ar,en}, municipality?:{key,ar,en,status},
            source:{key,ar,en}, class, classLabel:{ar,en}, actionable,
            count, remaining, dueByYearEnd, oldestDaysOverdue, overdue/notYetDue/dueUnavailable/partial:{count,amount},
            evidence:{enforcementLinked,objected,objectionRecorded,unresolvedLinkage,ineligibleReferral,proposedLink,aged180,partial,dueUnavailable:{count,amount},oldestDaysOverdue},
            blockers?:[{key,ar,en,count,amount,drill}]   (class A only: the reason, kept apart),
            recommendedAction:{key,ar,en}, expectedImpact:null, expectedImpactReason:{ar:'غير متاح',en:'Not available'},
            contributionToGap:{level:'entity',entityGap|null,share|null},
            drill:{route:'/collection',scope:{…,from:'2000-01-01',to:cutoff,amanah,source,muni?},filters:{state:'open',allPeriods:true,planLine:{cls}}},
            rankInputs:{actionable,cellActionable,entityGap,remaining,oldestDaysOverdue} } ],
  cells:[ entity × [municipality] × source roll-up: {id,rank,remaining,actionable(B+C),aged(D),blocked(A),byClass,oldestDaysOverdue,contributionToGap,drillActionable} ],
  entities:[ per-entity roll-up ],
  totals:{count,remaining,dueByYearEnd,byClass:{A..U:{count,remaining,dueByYearEnd,lines}},actionable,needsDecision,blocked,lines},
```

Default order (not a score): largest actionable cell first → the entity's gap → class order → line balance → id; `rank` = position. The page ranks as it sees fit from `rankInputs` / `cells`.

### Decisions applied (D-10 and consequences)
- **Classes (D-10 recommendation):** A blocked · B ≤ 180 d · C due by year-end · D > 180 d separate · expected impact «غير متاح». Boundaries: 180 days = B, 181 = D; due on 31 Dec = C, due 1 Jan = E; the year is the cut-off year (`yearEndOf`).
- **Two classes added to make the partition complete (needs owner confirmation):** **E** «يستحق بعد نهاية السنة» (not yet due, due after year-end — not actionable this year; empty in the compact world) and **U** «تاريخ الاستحقاق غير متاح» (own class, never overdue). Without them Σ lines would not equal the stock.
- **Precedence A > U > D > B > C > E**, one invoice one line; Σ lines = stock net unpaid to the SAR (national, Jeddah, municipality + explicit groups, organisation, restricted geographic access — all tested), and every line's drill count/total = `list()`.
- **Class A members** follow `07 §3`: confirmed enforcement link or Sanad-feed order (`derive`'s «referred» test; a withdrawn link is no referral), an open objection (`cls = objection`), unresolved linkage, ineligible referral. With the default rules (SND-1 and OBJ-1 on) enforcement-linked and objected invoices are *excluded* and therefore sit in `separate.excluded`, not in a line; they appear in class A only when those rules are off or for the data-linkage blockers. A's action is «متابعة الإجراء القائم — لا إحالة جديدة» (enforcement/objection) or «حسم ربط البيانات قبل أي إجراء — لا إحالة جديدة» (data blockers). Which blockers belong to A stays a business confirmation (D-10).
- **Excluded and cancelled invoices** are never in a line and never in the totals; they are reported apart (`separate`).
- **No recovery estimate** anywhere (`expectedImpact: null`, reason «غير متاح»); the `evidence` block holds counts/amounts of observed attributes, no causal wording.
- **Gap contribution** is entity-level only (no source target). `share = entityGap ÷ Σ supplied gaps` (null when the sum is not positive or the entity is not supplied); entities ahead of plan may be supplied with negative values. A restricted viewer's gaps must be computed by the page on the full entity set (targets never depend on visibility) and passed in; the share is relative to what is supplied.

### Drill (`filters.planLine`) — one edit outside the owned files
No combination of existing list filters can express «not blocked» (blockers are a union of classes and cannot be negated), so exact parity for B/C/D/E/U lines was impossible without a filter. `server/lists.js` therefore got an additive hook `filters.planLine = { cls: 'B' | ['B','C'], blocker?: 'objection' }` that calls the same `planLineMatches` the lines are built from. A drill needs the module `invoices_uncollected` (it is `state:'open'`); a planning-only user is refused by the list endpoint — page-level wiring (the `/collection` page must pass `planLine` through its filter builder `uncollectedListFilters`, and use `scope.from = 2000-01-01` / `allPeriods`) is the page agents' job. If the lead prefers not to touch `lists.js`, the hook is the only coupling to remove (drill parity then cannot be exact).
