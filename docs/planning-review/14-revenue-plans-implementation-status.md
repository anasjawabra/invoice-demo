## 2. Rules in force (what a person sees)
* A plan is a **named, saved configuration** (scope, period, target, allocations, optional municipal allocations, monthly distribution, advanced assumptions). No states, no approval, no versions UI, no status dropdown, no editable owner. The owner is the authenticated creator (stable user id), read-only; «آخر تعديل» is separate.
* **Save checks** (shown only as validation messages when a save fails): target > 0 · Σ allocations = target to the riyal · allocations inside the scope · explicit monthly profile · manual months exactly 10 000 bp · municipal Σ ≤ the Amanah's amount (only when municipal rows exist) · actor authorised. Names: trimmed, 1–80 characters, unique among the plans the person sees.
* **Editing is a working copy** in the browser (live preview, «تغييرات غير محفوظة»); nothing is stored until «حفظ الخطة». The system plan and plans a person may not edit are saved as a new plan.
* **Headline measures:** target · collected + «نسبة تحقيق المستهدف حتى تاريخه» · «نسبة الإنجاز مقابل المخطط» + the signed deviation · expected amount + «نسبة تحقيق المستهدف المتوقعة بنهاية الفترة» + the gap. No tolerance badge, no probability.
* **Defaults / assumptions (not business approvals):** January–December period preset; equal monthly distribution labelled «افتراض»; the illustrative system plan = 66 % × the communicated budget, allocated by revenue-appropriation share, set as the 2026 reference; forecast = mean of the last three complete observed months.
* **Municipality:** the view scope (Amanah → municipality) is a URL filter, never saved into the plan; a municipality without an allocation says «لم يُحدد مستهدف لهذه البلدية» (no Amanah target is reused); a municipal-only viewer never receives the Amanah total.

## 4. Legacy device record and import
* The retired page kept its targets in the browser under the key `ib_plan_targets_v1`. **Nothing in the application writes or deletes that value** (guarded by `tests/plans-removed.test.mjs`). A small read-only reader, `src/data/plans/legacyStore.js`, is the only code that names the key; `planDefaults.legacyStoreToContent / legacyRecord` map it to a plan.
* **Import notice** (`src/components/plans/LegacyImportNotice.jsx`, mounted on `/planning/:planId`): when this browser holds a saved record for a year, the person may import (all-entities access, not read-only), and the shared plans hold no plan imported from the same record (`legacy.versionId` + `savedAt` + `year`), a dismissible notice says «لديك مستهدف محفوظ على هذا الجهاز (2026) — يمكن استيراده كخطة جديدة» with «استيراد كخطة». It calls `importLegacyPlan(year, store)`; the plan is created ownerless with the original metadata kept, appears in the selector, a repeat answers 409 (the existing plan is named), a failed save check (422) or a validation error (400/403) is listed plainly. The browser value is never deleted or modified.

## 8. Limitations (stated, not hidden)
* **Local-demo storage.** The plan store is one JSON file written atomically by one process. It survives a restart in file mode only. On a read-only host such as Vercel it falls back to the OS temp dir or memory: **not durable across cold starts and not shared across function instances**. It is not deployment-ready persistence; there is no cross-process locking. (The UI does not carry this note any more; it lives in these docs and the spec.)
* The browser Back / Forward buttons are not covered by the unsaved-changes guard (BrowserRouter has no blocker API); route changes by links, plan switching, the new-plan button and closing the tab are.
* The Layout sidebar / page title still reads «تخطيط إيرادات التحصيل» (navigation strings were not part of this work).
* The action-gate `planning.update` still exists in the access model (the page decides editing from the read-only role and the planning scope; the server refuses too).
* `CollectionChart.jsx` and `UnitBar.jsx` in `src/components/strategic` were already unreferenced before this work and were left untouched.
